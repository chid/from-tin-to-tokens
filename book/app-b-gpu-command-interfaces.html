Appendix B: GPU Command Interfaces

The AQL kernel dispatch packet

64 bytes, little-endian, and the offsets are exact.

OFFSET FIELD SIZE DESCRIPTION
0 header 2 Packet type, barrier bit, fence scopes
2 setup 2 Number of grid dimensions (1–3)
4 workgroup_size_x 2 Work-items per workgroup, X
6 workgroup_size_y 2 Y
8 workgroup_size_z 2 Z
10 reserved0 2 Must be zero
12 grid_size_x 4 Total work-items, X
16 grid_size_y 4 Y
20 grid_size_z 4 Z
24 private_segment_size 4 Scratch bytes per work-item
28 group_segment_size 4 LDS bytes per workgroup
32 kernel_object 8 VA of the kernel descriptor
40 kernarg_address 8 VA of the kernel argument buffer
48 reserved2 8 Must be zero
56 completion_signal 8 VA of anamd_signal_t, or 0

The three 8-byte fields are naturally aligned at 32, 40, and 56, grid sizes are 32-bit while workgroup sizes are 16-bit, and kernel_object precedes kernarg_address . Reversing those two produces an immediate fault, which is at least a fast failure.

The header

BITS FIELD VALUES
0–7 packet type 1 = INVALID, 2 = KERNEL_DISPATCH, 3 = BARRIER_AND, …
8 barrier 1 = wait for all preceding packets to complete
9–10 acquire fence scope 0 = none, 1 = agent, 2 = system
11–12 release fence scope 0 = none, 1 = agent, 2 = system

The barrier bit is bit 8 , and bits 9 and 10 are the acquire fence scope. For cross-GPU visibility both fence scopes have to be system , since agent scope orders only within one device, and that’s the usual cause of collectives that pass their tests and go wrong under load.

The doorbell

Write the packet index , the value returned when you reserved the slot, rather than a byte offset or a count.

letindex=queue.reserve_slot();// returns the slot's index
queue.write_packet_body(index,&dispatch);// header still INVALID
queue.publish_header(index,header_word);// release store, hands it over
queue.doorbell.store(index,Ordering::Relaxed);

The release store that publishes the header is the handover, not the doorbell. A slot whose header reads INVALID is one the command processor skips, so the header must go out last and as a single store.

Writing index + 1 to the doorbell tells the processor that a slot you haven’t published is ready. It fetches a slot still marked INVALID and waits on it, so the symptom is a queue that quietly stops progressing rather than an error.

Completion signals

An amd_signal_t is a 64-byte structure whose value field the command processor updates atomically. Poll it, or bind it to an event and wait on the kernel. In a chain, only the final packet needs one.

The CUDA equivalent

CUDA presents streams and events rather than a packet format. A stream is roughly an AQL queue, an ordered command sequence. An event is roughly a completion signal. cudaLaunchKernel constructs and enqueues the launch, hiding the binary format. And CUDA Graphs are roughly chained dispatch, a captured dependency structure replayed with one call.

The underlying mechanism is the same, ring buffer and doorbell and completion, but the format isn’t public and isn’t intended to be constructed directly. That asymmetry is the practical reason a from-scratch stack targets AMD.

The universal abstraction

Whatever the vendor, you have a ring buffer the host writes commands into, a doorbell the host writes to announce them, a completion signal the device updates when work is done, and memory ordering connecting the three at an explicit scope. Understanding that pattern matters more than knowing any specific packet layout.
