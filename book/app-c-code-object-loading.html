Appendix C: Code Object Loading

Compilation

GPU kernels get written in a C dialect, OpenCL C or HIP or CUDA C, or in a kernel DSL, and compiled to a hardware-specific binary at build time.

On AMD , clang --target=amdgcn-amd-amdhsa -mcpu=gfx950 produces an AMDHSA ELF containing code, data, and metadata for a specific architecture. There’s no portable intermediate form in the usual pipeline, so the binary targets one GPU family.

On NVIDIA , nvcc or NVRTC produces PTX, a virtual ISA, or SASS, native code, or both. PTX gets JITcompiled by the driver at load time, which provides forward compatibility at the cost of a JIT step.

The AMDHSA ELF

Inside you’ll find PT_LOAD segments containing code and data, kernel descriptors , a 64-byte structure per kernel emitted as a symbol named <kernel>.kd holding the entry-point offset and register counts and segment sizes and configuration bits, and notes , a msgpack-encoded metadata note describing each kernel’s arguments with names and sizes and offsets and alignments and address spaces, plus the target architecture and code object version.

A from-scratch loader

Validate the ELF header, checking magic and 64-bit and little-endian and machine equal to EM_AMDGPU . Verify the target architecture from the notes matches the device and the code object version matches what your dispatch path assumes, because a gfx942 object on a gfx950 device fails in ways that look like a broken kernel. Allocate device memory covering the span of PT_LOAD segments with execute permission and the required alignment. Copy each segment to its virtual address and zero the BSS tail where memsz > filesz . Parse the symbol table and record the VA of each <kernel>.kd , which becomes the kernel_object field of the dispatch packet. Then parse the metadata note for the kernarg layout and use it to build kernarg buffers.

That last step is the one most often skipped and most often regretted, since hand-written kernarg offsets drift silently when a kernel’s signature changes, and the symptom is a kernel reading a pointer out of the middle of two integers.

Alignment requirements

Three alignments have to hold or the dispatch faults or misbehaves. The kernel descriptor’s VA must be 64-byte aligned. The kernarg buffer’s VA must meet the alignment in the metadata, commonly 16 bytes and sometimes more. And the signal’s VA must be 64-byte aligned.

Assert all three at dispatch time, since they’re cheap checks that convert hardware faults into error messages.

Embedding

staticKERNEL_BYTES:&[u8]=include_bytes!(concat!(env!("OUT_DIR"),
"/kernels.co"));

The build script compiles the kernel and writes it to OUT_DIR , the binary embeds it, and there are no external files and no possibility of kernel and host drifting apart between builds.

Against** **`cuModuleLoad

NVIDIA’s cuModuleLoad performs ELF parsing, JIT compilation, memory placement, and symbol resolution in one call, which is the usual trade, convenience and forward compatibility against control and visibility. A from-scratch loader tells you exactly what’s in the object and exactly where each byte went, which matters when you’re debugging why a kernel reads garbage.
