Appendix A: Rust Patterns for GPU Programming

Each pattern is presented as a lesson, what it prevents, what it enables, and the engineering context that makes it worth the trouble.

repr(C)` for kernel ABI structs

This prevents struct layout mismatch between Rust and the kernel. Without #[repr(C)] Rust may reorder fields for packing, and the ioctl writes the right bytes to the wrong offsets, which is silent corruption that can change with a compiler version. It enables direct ioctl calls from Rust that stay auditable field by field against the kernel header.

#[repr(C)]
#[derive(Debug, Default, Clone, Copy)]
pub struct AllocMemoryOfGpuArgs {
    pub va_addr: u64,      // to KFD
    pub size: u64,         // to KFD
    pub handle: u64,       // from KFD
    pub mmap_offset: u64,  // in: userptr; out: mmap offset
    pub gpu_id: u32,       // to KFD
    pub flags: u32,
}

/// AMDKFD_IOC_ALLOC_MEMORY_OF_GPU = AMDKFD_IOWR(0x16, ...)
pub fn ioc_alloc_memory_of_gpu() -> libc::c_ulong {
    iowr::<AllocMemoryOfGpuArgs>(0x16) as libc::c_ulong
}

pub unsafe fn alloc(fd: RawFd, args: &mut AllocMemoryOfGpuArgs) -> i32 {
    // Explicit block: `unsafe fn` no longer carries an implicit unsafe body.
    unsafe { libc::ioctl(fd, ioc_alloc_memory_of_gpu(), args as *mut _) }
}

Non-negotiable for any Rust code calling a C ABI, and the size assertion is not decoration either. amdkfd dispatches on the command number and zero-fills a short argument struct rather than rejecting it, so a struct missing its trailing fields is accepted and the missing values read as zero. The assertion is the only thing that turns that into a build error instead of a call against the wrong device.

Compile-time layout assertions

These prevent silent ABI drift in any struct shared with hardware or the kernel, meaning dispatch packets, signal structures, and ioctl arguments. They enable the cheapest possible ABI test, running on every build with no harness at all.

const_:()=assert!(core::mem::size_of::<AqlKernelDispatchPacket>()==64);

For structures where field offsets matter, the AQL packet being the obvious case, assert offsets too. Rust’s offset_of! makes that a one-liner per field, and those lines have caught more real bugs per character than any other code in a driver-level crate.

OwnedFd` for device handle lifetime

This prevents use-after-close. The device fd has to outlive every allocation and queue, and if it closes early, GPU operations fail in ways that look like hardware problems. It enables the fd’s lifetime to become an ownership invariant, since the Kfd struct owns the OwnedFd and DeviceBuffer s hold Arc<Kfd> , so the fd can’t close while any buffer exists.

It’s the Rust equivalent of RAII for file descriptors with the additional guarantee that the type can’t be duplicated accidentally.

Drop` for GPU memory

This prevents VRAM leaks, the most common failure mode in a long-running server, and double-frees. It enables RAII for device memory, so spatial safety comes free.

The limit is that Drop gives spatial safety and not temporal safety, since the GPU may still be reading the buffer when it runs and no borrow can express a borrow held by hardware. Wait on the relevant completion signal first, and let the unretired-dispatch counter tell you whether you need to.

Cell` for hot-path interior mutability

This prevents the cost of RefCell ’ s borrow flag or Mutex ’s atomic on a path running thousands of times per second, and it enables zero-cost mutation through a shared reference in the single-threaded dispatch loop.

Cell<T> requires T: Copy , which suits counters and indices, and its most valuable property isn’t performance. Cell isn’t Sync , so if someone later tries to share the queue across threads the compiler objects rather than the hardware.

Arc` for shared device handles

This prevents duplicating a device fd, which drivers either reject or turn into a double-close hazard, and it enables several GpuDevice values sharing one Kfd and its process VM.

The atomic refcount is negligible next to any GPU operation, and for multi-GPU code in one process this is the natural ownership model.

include_bytes!` for embedded GPU kernels

This prevents runtime file I/O for kernel loading along with a class of deployment bugs where the binary and its kernels drift apart, and it enables self-contained binaries, since the kernel bytes are &'static [u8] available immediately.

staticATTENTION_CO:&[u8]=include_bytes!(concat!(env!("OUT_DIR"),
"/attention.co"));

The code object gets produced by a build.rs step invoking the GPU compiler, so embedding it means the kernel and the host code are versioned together, which matters more than it sounds because a mismatched kernel ABI produces garbage rather than an error.

Newtype for device pointers

This prevents pointer confusion, since a device VA is a u64 indistinguishable in C from a host pointer or a handle or a length, and it enables compile-time prevention of the most dangerous class of GPU bug.

pub struct DeviceBuffer {

handle:u64,
va:u64,// not reachable as a bare integer from outside
size:u64,
kfd:Arc<Kfd>,
}

Zero-cost, and it composes. A KernargBuilder accepting only &DeviceBuffer for pointer arguments makes an entire error class unexpressible.

Typed states for lifecycle

This prevents using an object before it’s ready, dispatching to a queue before ACQUIRE_VM or reading a buffer before its DMA completes, and it enables encoding the initialisation sequence in the type system so that Device<Unmapped> simply has no dispatch method.

The strongest form, typestate, is often more ceremony than it’s worth, but for a small number of genuinely ordered operations, Chapter 5’s order of operations being the obvious set, it removes a category of bug otherwise found only on hardware.

Errors that name the thing

This prevents the failure mode where a stack returns Err(()) from ten layers down and the operator sees “operation failed”, and it enables diagnosis from a log line.

At this layer, attach the ioctl name, the gpu_id , the VA, the size, and the errno to every error, which anyhow::Context or an equivalent makes cheap. The measure of a good error here is whether it identifies the offending buffer without a debugger.
