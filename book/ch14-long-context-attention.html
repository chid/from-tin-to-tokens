Part III: Attention and the KV Cache

Long-Context Attention

Everything so far assumes the model can attend to its full context and that you’re willing to pay for it, and at a million tokens neither assumption survives contact with economics. A model trained at 32K doesn’t magically work at 1M, and even if it did, attending to the whole history for every token would cost more than anyone wants to spend. This chapter covers the two families of technique that make million-token serving real, one for each problem.

The two problems

Extrapolation. A model trained with RoPE at a given base frequency and maximum length doesn’t automatically work beyond it. Attention scores degrade badly at unseen relative distances, and the output becomes incoherent well before you run out of memory.

Cost. Even if the model extrapolates, attention over the full history is linear per token in context length for decode and quadratic in total for prefill, so at a million tokens prefill alone is enormous and decode reads gigabytes per token per layer.

Production 1M-context deployments solve both, and the techniques are independent.

RoPE and its base frequency

Recall RoPE from Chapter 22, where dimension pair i rotates by θ_i = p · base^(−2i/d) at position p . Low-index dimensions rotate fast, carrying local information, while high-index dimensions rotate slowly and carry long-range information.

The base frequency is the main knob. Llama 1 and 2 use 10,000, Llama 3 raised it to 500,000, and Llama 3.1’s 128K variant layers a rope_scaling block on top of that base. Qwen3-235B-A22B uses 1e6 at 40,960 positions in its original release and 5e6 at 262,144 positions in the Instruct-2507 refresh. Raising the base slows the decay of positional frequencies, so slow dimensions complete fewer rotations across the context and stay distinguishable at long distance, which is why models intended for long context get pretrained, or continued-pretrained, with a raised base.

Position interpolation, NTK scaling, and YaRN

To push a trained model past its training length without retraining it, three approaches build on each other.

Position Interpolation scales positions down by the extension factor s , using p / s instead of p , so every relative distance falls back inside the trained range. Simple, works with brief fine-tuning, and it compresses the high-frequency dimensions that were carrying local information, which costs shortcontext quality.

NTK-aware scaling scales the base instead of the positions, spreading the interpolation unevenly across dimensions so high frequencies are barely touched and local resolution survives while low frequencies get interpolated and range extends. It works without fine-tuning to moderate extension factors.

YaRN is the refinement that became standard. It combines frequency-dependent interpolation, where dimensions whose wavelength is short relative to the trained context are left alone, dimensions whose wavelength exceeds it get interpolated, and a band in between is blended, with a temperature adjustment to the attention logits that compensates for the entropy change longer contexts cause. It reaches large extension factors with modest fine-tuning and it’s what most published long-context configurations use.

Two things to get right as an engine builder. YaRN’s parameters live in the model config, under rope_scaling with factor , original_max_position_embeddings , and beta parameters, and they must be applied exactly as trained, since a mismatch between config and kernel produces a model that’s subtly wrong rather than obviously broken. And static YaRN scaling degrades short-context performance because it applies the extension whether or not the sequence needs it, so if you serve mixed lengths you either serve two configurations or use a length-aware variant.

Dual Chunk Attention

Interpolation still asks the model to handle relative distances it never saw. Dual Chunk Attention instead remaps positions so no distance exceeds the trained range, dividing the sequence into chunks and using three position index schemes, one within a chunk, one between adjacent chunks, and one between distant chunks, such that every computed relative position stays inside what the model was trained on.

DCA is training-free. Combined with YaRN it’s the published path by which Qwen2.5-1M and the Qwen3-2507 models reach a million tokens, and it’s supported in vLLM and SGLang. The engine cost is real but contained, since attention has to be computed with position indices derived from the chunk scheme rather than absolute positions, meaning the kernel takes a position map rather than a scalar offset.

Sparse attention

Extrapolation solves quality. Sparsity solves cost, and it’s where the frontier is.

The empirical basis is that attention at long context is extremely concentrated, so for most heads and most queries a small fraction of keys carries almost all the probability mass. The exploitable structure shows up in a few recurring patterns, a local window, a set of global or sink tokens, strided diagonals, and a query-dependent set of semantically relevant blocks.

Training-free selection at inference is what MInference does, profiling each head offline, assigning it one of a few sparse patterns, and building the sparse index dynamically per head at inference time, with reported speedups reaching roughly 10× for 1M prefill on A100-class hardware while retaining accuracy. Related approaches, Quest and DuoAttention and various block-sparse top- k selectors, estimate perblock relevance cheaply and attend to the top blocks only.

Trainable sparsity is Native Sparse Attention’s answer, making the sparse pattern part of the architecture and training with it, combining compressed coarse tokens, selected fine blocks, and a sliding window through a learned gate. Because the model is trained sparse there’s no train-inference mismatch to recover from, and the pattern is hardware-aligned by construction.

Production sparse attention is DeepSeek Sparse Attention, the version that shipped at scale, where a lightweight indexer selects a fixed budget of tokens per query, on the order of 2,048, and attention runs over that budget. Attention compute at 128K context falls by roughly 98% while long-range retrieval survives, which changes the economics of long context outright. As of 2026 it powers long-context inference in DeepSeek’s and other frontier MoE models, and serving engines expose it through dedicated prefill and decode backends.

What sparsity does to the rest of the stack

This is the part that surprises implementers, and it’s why sparse attention belongs in a systems book rather than only a modelling one.

The KV cache doesn’t shrink. Selection reduces reads, not storage, because any token might be selected by a later query. Sparse attention and KV quantisation are complements rather than alternatives.

Gather replaces stream. A dense decode kernel streams contiguous blocks and is bandwidth-bound with perfect locality, while a sparse kernel gathers scattered blocks, so achieved bandwidth per byte requested drops sharply and the block granularity of selection, not the token granularity, decides efficiency. Selecting whole pages aligned to your KV block size is worth a great deal here.

The index has a cost. Whatever computes the selection runs on every query, and if it costs more than a few percent of the attention it replaces the gain evaporates, which is why production designs use a small learned indexer or a compressed-token scan rather than an exact top- k over the full cache.

Scheduling changes. Per-request attention cost stops being a function of sequence length alone, which breaks the cost models a scheduler uses to pack batches, as Chapter 16 explains.

Streaming and bounded-cache serving

A separate regime worth distinguishing, because confusing it with long-context understanding is a common way to ship a regression. In unbounded conversation where you don’t need recall of the distant past, only fluent continuation, StreamingLLM’s finding is the practical one. Keep a handful of initial tokens as attention sinks plus a rolling window of recent tokens and generation stays stable indefinitely, where naively dropping the oldest tokens collapses immediately. Chapter 32 explains why.

What a 1M-context path actually looks like

Assembled from everything above, a concrete configuration.

A model pretrained with a high RoPE base, extended with YaRN and DCA to 1M positions. Chunked prefill with a large chunk, 32K being a published choice, so activation memory stays bounded, which is a 96%-plus reduction against prefilling a million tokens at once. Sparse attention during prefill, patternbased or learned, to cut the quadratic term. FP8 KV cache with per-token scales, giving 96 GB rather than 192 GB for the sequence. Paged KV with large blocks so sparse gathers stay page-aligned. And prefix caching, so the 1M-token document gets prefilled once and reused across the many queries that follow.

That last point deserves emphasis, because almost every deployed million-token workload is one enormous shared context with many queries against it. A system that prefills brilliantly and can’t reuse the result is solving the wrong half of the problem.

Key Concept

Long context has two independent problems, extrapolation and cost. YaRN, with frequency-dependent interpolation plus logit temperature, and dual-chunk attention, which remaps positions so no relative distance is unseen, solve extrapolation training-free or nearly so. Sparse attention solves cost, with production systems attending to a bounded per-query budget and cutting attention compute at 128K by around 98%. Sparsity reduces reads rather than storage, so it composes with KV quantisation rather than replacing it, and it turns a streaming kernel into a gathering one, which is a systems change rather than a kernel change.

Exercises

  1. Given a model trained at 32K with RoPE base 1e6, compute the extension factor needed for a million tokens and describe what YaRN does to the lowest- and highest-frequency dimension pairs.

  2. Explain why static YaRN scaling degrades short-context quality, then design a serving policy that avoids the degradation for a mixed-length workload.

  3. A sparse decode kernel selects 2,048 of 1,000,000 tokens per query and achieves only 15% of the dense kernel’s bandwidth. Explain, and propose two changes to the selection granularity that would improve it.

  4. Build: implement top- k block selection over a paged KV cache using per-block key summaries. Measure recall of the true top- k tokens as a function of block size, and the wall-clock cost of the selection step.
